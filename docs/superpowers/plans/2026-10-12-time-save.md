# 第五阶段：时间、天气与存档实施计划

目标：提供从春季 1 日 06:00 开始的可持续经营，关闭页面后恢复进度。

设计：GameState 保存总日数、游戏分钟、天气随机种子及最后结算日。日历派生年、季节、季节日和星期；20 小时游戏时间对应 900000 毫秒。睡觉和 02:00 自动跨天调用同一接口，每日结算最多一次。暂停、弹窗及隐藏页面停表，离线不补时。天气按配置生成并持久化，世界遮罩与雨线只作用于 Phaser 画面，DOM UI 不变暗。不增加图片资源。

存档 schemaVersion=4。纯编解码模块验证所有必要字段、物品上限、交易状态、日期、位置及作物；存储适配器处理 localStorage 异常。写入前验证当前状态和已有存档，损坏/不兼容旧档拒绝覆盖；读取失败不替换内存进度。地图适配层进一步校验位置碰撞与可耕区。

实施顺序：

1. 时间测试先失败，再实现日历、时钟、跨天去重、天气与种植结算接入。
2. 存档测试先失败，再实现序列化/反序列化与存储读写保护。
3. 接入小屋睡觉、自动保存、手动保存/读取、首页继续、暂停和天气光照。
4. 检查类型、完整测试、构建；浏览器验收暂停、睡觉、保存、刷新继续及恢复经营数据。

重点验证：季节/年份/星期边界、负数或异常时间输入、重复睡觉、雨天生长、坏 JSON/缺字段/超限物品、存储拒写、障碍中的恢复位置、失败读取不破坏当前经营状态。
