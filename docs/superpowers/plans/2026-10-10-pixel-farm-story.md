# Pixel Farm Story 项目实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 分阶段构建原创单机 2D 像素农场游戏，先交付可玩的种植闭环，再扩展经营、探索和 NPC 交互。

**Architecture:** 使用纯 TypeScript 规则系统维护 GameState，以类型化配置驱动作物与商品等内容。Phaser Scene / UI 展示状态并派发玩家操作；Tiled 地图和 localStorage 通过独立适配层接入。

**Tech Stack:** TypeScript strict、Phaser 3、Vite、Tiled JSON、Vitest、浏览器 localStorage。

**Spec:** [AGENTS.md](../../../AGENTS.md) 中的项目定位、15 条开发规范与分层约定；本文件的架构与范围段落是初步设计建议。

## Global Constraints

- 严格遵守 AGENTS.md 的全部 15 条规范及东八区时间约定。
- 按用户 2026-10-12 的要求采用 32×32 基础网格、整数倍画面缩放、像素对齐与关闭平滑插值；以用户提供的 PNG 为主，缺少后续新图片时先询问用户。
- 采用原创或合法授权内容；不使用未经授权的商业游戏素材。
- 不默认引入 React、Vue 或后端；本地单机与 localStorage 是基础范围。
- GameState 是持久化状态的唯一事实来源；规则不依赖 Phaser 或浏览器 API。
- 各阶段完成状态以实际交付与检查证据为准；未来计划中的命令不能作为已执行结果。

## 建议架构与演进方式

推荐先实现“走到农田 → 耕地 → 播种 → 浇水 → 结束一天 → 成熟 → 收获”的垂直闭环。这样能尽早检查玩法、状态、地图、输入与 UI 是否配合；随后接入存档，再扩展买卖、探索和 NPC。

另一种路线是先完成所有规则系统，能更早覆盖纯逻辑，但较晚发现交互问题。也可以先完成地图与画面，但大量视觉投入可能早于玩法验证。本项目采用先完成小型可玩闭环的建议路线。

建议按需要逐步引入以下目录，当前不创建占位源码：

```text
src/
  main.ts                 # 页面入口与游戏启动
  game/createGame.ts      # Phaser 配置、像素缩放与窗口适配
  game/scenes/            # Boot、Preload、World、UI 等展示职责
  game/input/             # 输入映射、动作派发和交互焦点
  domain/state/           # GameState、初始状态与状态类型
  domain/systems/         # 时间、种植、背包、经济、NPC 等规则
  data/                   # 作物、物品、商品、NPC 等类型化配置
  adapters/maps/          # Tiled 校验、解析与地图查询
  adapters/storage/       # 存档编码、校验、迁移与 localStorage 读写
  ui/                     # 统一样式与可复用 UI 组件
public/assets/            # 原创或合法授权素材及 Tiled JSON 地图
tests/                    # 核心规则与适配器测试，随实际模块创建
docs/                     # 地图契约、素材来源、阶段记录与验收说明
```

规则系统通过类型化操作返回成功或失败结果；可恢复的失败（资源不足、地块不合法、空间不足）提供明确原因，失败时不产生部分写入。应用协调层在规则成功后通知展示层刷新。具体函数签名在对应阶段的小计划中确定，避免过早建立通用框架。
